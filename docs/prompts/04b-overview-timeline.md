# Prompt 4b: Overview timeline with region selection (`ui` crate)

Context: the attached CONTEXT.md describes the project and the working rules; the repository's real source is the contract. Implement ONLY the `OverviewTimeline` widget in the `ui` crate, with a demo `crates/ui/examples/overview_demo.rs`. It sits at the very top of the window and shows the WHOLE audio file (not the zoomed view).

Requirements:
1. Draws a compact whole-file waveform (use a closure `peaks(time_range, pixel_width) -> Vec<(min,max,rms)>` so there is no dependency on the analysis crate), faint measure lines (passed in as a `&[f64]` of measure start times), a rectangle showing the currently visible part of the main view (`TimelineView`; dragging this rectangle pans the main view, dragging its edges zooms it), the playhead, and a ruler with time labels (m:ss) that adapts its tick spacing to the width.
2. Region selection: click-drag on the timeline (outside the viewport rectangle's handles; hold Shift or use a "select" mode if that conflicts) creates a selected region [start, end] shown as a translucent highlight with two draggable handles. Double-click clears the selection. Optional snapping of the region edges to the nearest measure/beat line (hold Ctrl to snap, `snap_region: bool` option in the widget). Also support dragging the selected region as a whole.
3. The same selection must be creatable from the main view: expose `RegionSelection { start_sec, end_sec }` as a type in `ui::view` and accept it as a `&mut Option<RegionSelection>` so the spectrogram widget can also draw it (translucent overlay) and edit it (Alt+drag on the spectrogram's ruler strip). The overview timeline only owns the interaction on its own strip.
4. Events: `OverviewEvent::{SeekRequested(sec), RegionChanged(Option<RegionSelection>), ViewportChanged{scroll_sec, pixels_per_sec}}`. A plain click (no drag) seeks.
5. Small loop button and a "play selection" button next to the strip (emit `PlayRegionRequested`, `LoopToggled(bool)`), with a tooltip. The loop flag and region are forwarded by the app to `audio::Player::set_region` / `set_loop` (these exist in the audio prompt).
6. Unit tests for the coordinate mapping and the region normalisation (start < end, clamped to the audio length, minimum length of 50 ms).
